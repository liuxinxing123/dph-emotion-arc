## 主文案（GitHub README 顶部 / 博客版）

### 情绪弧线导演：占位者众，存活者寡的赛道里，第一个「成熟级」

DeepSeek Harness 开源两个月，生态里「情绪陪伴」类插件是最早自发涌现的品类之一——也是死得最整齐的品类之一：7 个仓库合计 40★，4 个在创建后九天之内停更。它们都在做同一件事：让模型「演」出情绪（表情标签、神态协议、Live2D），没有一个接入真实情绪信号、没有一个做状态工程、没有一个承诺跨版本存活。

**dph-emotion-arc 做的是另一件事**——按编剧方法论把「情绪」做成显式工程对象：

```
用户消息 → 情绪识别（LLM 精判 BYOK + 零成本词典兜底）
        → 显式状态文件（强度 + 半衰期衰减 + 换标签迟滞 + 推断审计日志）
        → 对话策略映射（共情/倾听/降不确定，注入 + 稳态上下文）
        → 情绪记忆账本（冲突/和解/安抚/突破…，跨会话保留）
        → 酒馆卡人格感知（导入角色卡，一份资产多生态分发）
```

### 为什么说它「成熟」

- **29 例单测**：词典识别（含否定前缀/拉丁词边界两个实战修掉的 bug 用例）、LLM 响应容错解析、SillyTavern V2 PNG/V3 JSON 解析
- **适配矩阵**：零 `@deepseek-ai/*` 依赖、全部防御式调用、README 明确维护纪律（生态里每 2-4 周一次的破坏性变更面前，「你的 AI 伴侣这周失联」不是段子）
- **实机验收**：在真实 Harness 会话里跑通全链路（识别 → 注入 → 衰减 → 账本 → 角色卡），audit 日志可查
- **合规白名单**：工具/叙事定位，不提供拟人化持续情感互动，状态文件与审计日志本身就是「可追溯」的工程答案

### 快装（2 分钟）

```yaml
# 插件市场安装 dph-emotion-arc，或在 cordis.patch.yml 中：
- insert:
    - id: emotion-arc
      name: 'dph-emotion-arc'
      config:
        detectorMode: auto   # lexicon 零成本 / llm BYOK 精判 / auto 双引擎
```

发一句「气死我了，这破网又断了！！！」——输入框下方的芯片会告诉你，Agent 已经被通知该怎么接住你。

### 对编剧/内容创作者的一个钩子

插件支持导入 SillyTavern V2/V3 角色卡（一份创作，同时进酒馆生态和 DSH 生态）。情绪弧线 + 角色人格 = 「角色弧光」的工程化。需要语C 人设包、角色卡定制，或想把你的故事角色做成可交互资产——看仓库联系方式。

## 变体 B：小红书笔记（口语化，带 emoji）

标题：给 AI 装了「情绪仪表盘」之后，我发现编剧的活它终于能干了 🎭

正文要点：
- 玩 DSH 插件的应该都见过：情绪陪伴插件一堆，点进去全是「表情标签」「Live2D」——模型在演情绪，没人在测情绪。
- 我做了个「情绪弧线导演」：你发「气死我了」，它先识别（词典 + LLM 双引擎），再写进状态文件（会随时间衰减，跟真情绪一样），然后告诉 AI 该怎么接：先共情、不说教。

- 最狠的是能直接导入酒馆角色卡，你的 OC 换个生态继续活。
- 免费开源，MIT。想要人设包/角色卡定制的，评论区/私信见。
